# Cube Golden self-play performance root cause

Date: 2026-09-12
Branch: `codex/cube-golden-neural-proof`
Contract: unchanged Cube 4x4 Golden, 97 actions, 64 PUCT simulations, `cpuct=1.25`, `FPU=0`, positional superko, `komi=0.5`.

## Symptom and invalid run

`cube4-golden-transfer-seed1-v1` was stopped before canonical evidence collection and marked `PERFORMANCE_INVALID`. Its artifacts remain untouched; it produced 0/512 canonical games and is not training data or a scientific result. The invalidation reason is the pathological CPU-bound implementation, not a semantic failure.

The pre-fix profile used the fixed model and fixed 64-simulation search on four deterministic states. The raw reproducible output is [cube-golden-performance-benchmark-20260912.json](cube-golden-performance-benchmark-20260912.json), generated by [cube_golden_performance.py](../tools/cube_golden_performance.py).

## Root causes, measured

### ROOT CAUSE 1 — global history validation on speculative children

Every legal point probe called `apply_action`, which constructed a complete `GoldenState`. `GoldenState.__post_init__` then normalized every historical board, recomputed exact board keys, recomputed the rules fingerprint, and audited the whole history. A single pre-fix early-state search performed 12,514 full-history state constructions; the cProfile run attributed 1.747s of 2.328s cumulative time to `GoldenState.__post_init__`, with `_history` and `board_key` among the largest callees.

The fix keeps the ordered exact `superko_history`, adds an immutable exact `frozenset` membership index, and uses a trusted transition constructor only after local rule checks have completed. External constructors still perform the complete audit. On the long-history benchmark, full-history validations fell from 10,154 to 0 and search time fell from 15.323s to 0.287s.

### ROOT CAUSE 2 — duplicate legality scans and child allocation

Before the fix, each of 65 NN evaluations scanned legality, each of 65 expanded nodes scanned legality again at PUCT expansion, and the final root result scanned once more: 131 legality calls per 64-sim search. The scan performed 96 hypothetical full child transitions. The reference run recorded 12,640 `apply_action` calls and 12,514 validated child states.

The fix introduces `LegalActionContext` and `probe_action`. A node calculates its exact legal actions and mask once; the prepared context is reused by observation construction, NN evaluation, PUCT expansion, root result, and Dirichlet root noise. A probe returns exact capture/resulting-board data without allocating a child; a full trusted child is allocated only for the selected edge. The optimized run recorded 65 legality calculations, 6,303 exact probes, 64 actual child transitions, and 0 standalone `legal_actions` calls.

### ROOT CAUSE 3 — deep evidence audit was on the generation hot path

After every generated game, the old runner called the full replay audit. That re-deserialized every position, recalculated legality, rebuilt observations, and replayed the trace immediately after generation. This duplicated work that belongs at the chunk/evidence boundary. On a two-position deterministic smoke record, generation validation measured 0.136ms with the cheap local path versus 3.083ms for the full deep audit (`22.7x`).

The runner now performs cheap local shape/policy/selected-action checks during generation. `validate_chunk` performs the authoritative deep game and sample audits once per chunk; duplicate game/sample validation calls and the final second full replay are removed. Deep validation remains the default public API and continues to reject corrupted history, legal masks, policy targets, z targets, and model hashes.

## Remaining cost and ETA

The representative run shows that game length is separate from compute per decision: mean length was 65.06 plies, p90 130, max 187, and all 16 games reached formal double-pass. No resign, move cap, forced pass, batching, virtual loss, approximate legality, or terminal change was introduced.

Using the measured 16-game throughput as a conservative linear estimate:

- one 128-game self-play chunk: about **9.8 minutes**;
- four 128-game chunks: about **39 minutes** of self-play;
- one configured arena comparison (64 frozen starts + one 2-game empty-board control, 130 sequential games): about **67 minutes** using the measured 30.93 child-CPU seconds/game; the full three-primary plus three-progression arena suite is about **6.7 hours**.

These are capacity estimates, not canonical proof results. A new `cube4-golden-transfer-seed1-v2` run with a newly frozen M0 is required after this change; v1 must not be resumed.

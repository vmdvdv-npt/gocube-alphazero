# Отдельная сессия WSP v002: 64 + 2 прохода

Старая `EXPERIMENT_PROTOCOL.md`, v000/v001 и исходная сессия 6/10 не изменены.
`session64/session.json` создан до первой диагностики: 8 диагностических,
8 development и 48 holdout-проходов. После превышения численного допуска создано
отдельное `numerical-addendum2/session.json`: два прохода только для повторной
проверки алгебраического исправления. Общий лимит — **66**, старый manifest не
переписан. Это адаптивный эксперимент; не одноразовая генерация без обратной связи.

Проход означает один явно зарезервированный пакет позиций или партий, а не один
вызов torch. Запросы и ошибки сохраняются до/после исполнения; ошибка расходует
проход. `flock` защищает выделение номера и лимит. Разные пакеты можно исполнять
одновременно после атомарной записи reservation. Данные, модели и деревья у них
независимы. Исходники сохраняются по SHA-256 в `source-snapshots`.

## Отбор и фиксация

Development: 32 начала, seed 2026110302; до восьми игровых пакетов. Генерация
использует только штатный referee и новые случайные легальные истории длиной
4,8,12,16,20,24,32,40 ходов. Ни production replay, ни партии обучения не читаются.
Финальные 96 начал с seed 2026110399 созданы заранее, их хеш записан в manifest.
Совпадений конечных досок внутри каждого набора и между ними с учётом всех
648 симметрий тора нет. Разные количества случайных стартовых ходов дают
разнообразие, но **не представляют распределение человеческих или обученных
дебютов**; выводы ограничены этим startset.

До первого holdout создаётся `freeze.json`: байтовые хеши v002, v001 и M269,
хеш протокола и исполняемых исходников. После freeze запрещены development,
подмена модели, изменение исходников, незапланированная пара или MCTS-бюджет,
повторное резервирование того же пакета. Не допускается добор партий ради
значимости. Незавершённый/ошибочный пакет остаётся видимым; selective rerun нет.

## Итоговая матрица

Шесть сравнений, каждое по 192 партии = 96 одинаковых начал × смена цветов:

| Матч | Без поиска | MCTS-64 |
|---|---:|---:|
| v002 — v001 | 192 | 192 |
| v002 — M269 | 192 | 192 |
| v001 — M269 | 192 | 192 |

Всего 1 152 партии, 48 пакетов по 12 пар. Baseline v001–M269 нужен, чтобы не
приписать кандидату изменение сложности выбранных начал. Строгий критерий
устойчивого улучшения проверяется по прямому сравнению с v001; результаты
policy и MCTS показываются раздельно, в том числе если расходятся.

Без поиска: argmax по легальным policy logits, без внешних стратегических
эвристик. Это непосредственная greedy policy, отличается от temperature=1
пилота v000. Для обоих игроков одинаково. Поиск: штатный `SequentialPUCTSession`,
64 simulations на ход, cpuct 1,25, FPU 0, tree reuse ON, noise/resign OFF.
Групповая выдача листьев объединяет независимые партии для inference, не меняя
число simulations и порядок внутри дерева. Одна и та же Golden-реализация
правил/завершения и входной 5CH-контракт. Коми 1,5. Watchdog 1000 — техническая
ошибка, не ничья и не новая процедура scoring.

M269 — зафиксированный AZ23 lr-B из неизменённого `reference-lock.json`, 8×80.
Его checkpoint, metadata и arena evidence проверяются по SHA штатным loader.
Он используется только как соперник и для WDL-сравнения, не как источник весов.
WSP остаётся 8×120. Исполнение: FP32, CUDA, TF32 OFF, один CPU-thread на процесс;
до четырёх независимых пакетных процессов на имеющемся GPU. Это не Orchestrator
и не изменение его launch-интерфейса или production-процесса.

## Метрики и научные ограничения

Сохраняются все ходы, снятия, результат referee, цвет, начало, реальные параметры,
хеши, время и число игровых запросов inference. Дополнительные WDL-измерения
не входят в `model_calls` поиска. Каждые восемь реальных ходов **обе** сети
оценивают **одно** состояние; прогнозы не меняют выбор хода. После завершения
считается multiclass Brier по фактическому результату, сначала среднее внутри
игры, затем между играми. Это on-policy прогноз результата данного продолжения,
не oracle value и не оценка оптимальной игры. Ходы одной партии не выдаются за
независимые статистические примеры.

Счёт пары — среднее двух игр. Интервал Hoeffding строится по 96 ограниченным
[0,1] величинам, а не по 192 якобы независимым играм. Он консервативен; дополнительно
показывается Bonferroni-коррекция на два основных v002–v001 сравнения. Выбор
модели по development не даёт права использовать development в итоговом CI.
192 партии различают крупные эффекты; малый прирост может остаться неразличимым.
Число ненулевых весов, структурный PASS и отдельный успешный пример не являются
свидетельством усиления игры.

## Воспроизведение

Из `torus_weightspace_starter`, с Python 3.9+/torch 2.4.x/NumPy 1.x:

```bash
WSP_PY=/home/codex/projects/gocube-alphazero/.venv/bin/python
"$WSP_PY" v002/test_session.py -v
"$WSP_PY" experiment_cli.py zero-pass --writer v002/compiler.py --output /tmp/wsp-new-version
"$WSP_PY" v002/session.py init --session /tmp/wsp-new-session
"$WSP_PY" v002/audit.py --session /tmp/wsp-new-session --candidate /tmp/wsp-new-version/checkpoint.pt
# Затем явно разрешённые development-пакеты; после выбора:
"$WSP_PY" v002/session.py freeze --session /tmp/wsp-new-session --candidate /tmp/wsp-new-version/checkpoint.pt
"$WSP_PY" v002/final_evaluation.py --session /tmp/wsp-new-session --workers 4
"$WSP_PY" v002/summarize.py --session /tmp/wsp-new-session --output /tmp/wsp-new-summary.json
```

Выходные каталоги должны быть новыми. Для другой машины перенесите reference и
evidence с проверкой SHA; не изменяйте существующий reference-lock задним числом.
В репозитории большие отчёты могут лежать отдельными lossless `.json.gz` копиями
в `evidence`; их manifest содержит SHA исходного JSON. Оригинальные локальные
evaluation-файлы остаются неизменными.
